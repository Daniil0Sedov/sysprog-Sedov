# ЛР 1. Процесс изнутри

Система: Windows x64 · компилятор: Microsoft (R) C/C++ Optimizing Compiler Version 19.51.36260 for x64.

## Программа на C

Программа напечатала PID 39532, Диспетчер задач показал PID 39532. В Диспетчере задач показано 384 КБ памяти; в свойствах Process Explorer для того же запуска Working Set составлял 3 880 КБ. Это разные показатели памяти. Процессорное время в свойствах: 0:00:00.000.

Пока программа ждёт Enter, процесс заблокирован в ожидании ввода и не выполняет полезных вычислений, поэтому процессорное время практически не растёт.

В свойствах процесса показан 51 дескриптор. Среди дескрипторов виден `\Device\ConDrv` — устройство консольного ввода и вывода. В списке библиотек видны `kernel32.dll`, `KernelBase.dll`, `ntdll.dll` и `apphelp.dll`.

После завершения из монитора процесс исчез из списка, а в терминале снова появилось приглашение командной строки. Код завершения на скриншоте не показан, поэтому не определён. На последующих скриншотах PID отличается, так как программа запускалась заново после BSoD.

## Программа на Python

Имя процесса: `python3.13t.exe`, PID 11180, память в Диспетчере задач — 5 188 КБ. По показаниям Диспетчера задач это примерно в 13,5 раза больше, чем 384 КБ у процесса C на снимке 02. Значения относятся к разным запускам и моментам времени.

Общие библиотеки программ на C и Python: `kernel32.dll`, `KernelBase.dll` и `ntdll.dll` — они видны в списках обоих процессов. После обычного выхода процесс исчез из списка; код завершения на снимке не показан и не проверен.
